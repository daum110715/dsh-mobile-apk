# dsh-mobile-apk 0.14.10

> 版本：versionCode 54 / versionName 0.14.10（覆盖安装 0.14.9 的 versionCode 53）。
> 本文件面向用户：先写本版解决的问题，再写安装与升级、已知限制。
> 本版内容严格对应提交范围 `v0.14.9..33f1fd0b`（共 322 个提交）。33f1fd0b 之后合入主干的改动不在本版范围内，进 0.14.11。
> 双 ABI 产物的体积与 SHA-256 见本 Release 的 MANIFEST.txt。

## 新增功能

### 1. 内置控制台成为真正的终端，全屏程序可以用（#549、#554、#580）

管理中心里的控制台此前只能敲命令：没有 PTY，按键送不进去，没有作业控制，程序按 0x0 排版。在它里面跑 `termux-change-repo` 会直接报 "TERM environment variable not set."，跑 `vim`、`top` 则画不出内容。

本版补上三处缺件：PTY（由引擎自带的 node-pty 提供，不新增依赖、不新增构建面）、终端环境变量与 terminfo 可达性、以及页面侧的按键编码。控制台现在带 Tab、Ctrl-C、Ctrl-D、方向键的按键条，`top`、`vim`、`termux-change-repo` 这类全屏程序可以正常使用，键盘弹出时按真实行数重新排版。

同一批审计修掉八处控制台缺陷（#580）：关闭会话时终止协议根本没发出去，全屏程序的后代进程只能等强杀回收；反斜杠被二次转义导致一条命令被拆成两条执行；程序就绪前的首条命令被静默丢弃；降级模式下窗口尺寸变化被当成命令注入；启动失败的会话仍显示「可用」；降级模式写满 64KB 后永久卡死；大文件输出按小片段逐帧跨进程推送导致主线程 ANR；以及整屏双倍行距。

### 2. 管理中心一键换源（#551、#555、#575）

移动端改软件源此前要么敲 `sed`、要么跑 `termux-change-repo`（而后者在旧控制台里必然失败）。管理中心新增「软件源」一行，显示当前源，点一下循环切换，覆盖六个常用国内镜像。

写入是双份的：`sources.list` 与 `chosen_mirrors` 链接同时更新，否则下一次 `pkg update` 会按「链接不存在」随机重选源、把用户的选择覆盖掉。切换前先备份、切换后验证；验证不只看退出码——不可达的源同样返回 0，但索引是空的——所以失败会真的回滚，且回滚一并还原链接。快照刷新会整树替换运行时目录，刷新前后自动捕获与重放用户的选择。

### 3. 会话行菜单可以删除对话（#493、#496）

引擎此前只有归档、没有删除会话的接口。本版新增内置插件：会话行的「…」菜单里多一条「删除对话」，确认后删除磁盘上的会话目录，并刷新列表、索引与搜索。

删除只处理「正在运行」的会话：引擎会把打开过的会话都留在内存里，按「加载过」拒绝等于删不掉任何东西。反过来，活动探测失败、返回非数组、拿不到活动瀑布这三种「不知道」的状态一律按未知处理并拒绝删除，绝不把「不知道」当「空闲」。删除前先把会话从内存列表卸载并落盘，再删目录，避免删完还留在搜索结果里。目录先改名成 `.deleting-<时间戳>` 再递归删除，并发扫描看不到半删目录；进程死在两步之间留下的残留，下次启动时清扫。

### 4. 插件市场做成整页（#505、#517、#541、#556）

市场入口收到插件页的「添加插件」下拉里，点进去是整页而不是弹窗，旧的页签入口已隐藏。此前打开要等六次 120ms 的导航探测，搜索框只有 32px 高，返回是个 32px 的小箭头。

现在直接打开、零等待；搜索框 44px；页头固定并带「返回」，让开系统状态栏与安全区，内容区自己滚动，滚动时页头不跟着走。列表每页 96 条，上下各一条分页条，支持首末页、当前页前后各一页与页码跳转，双击省略号翻页。

按仓库折叠是一行一个仓库（仓库名、作者、star 数），展开后列出该仓库的子包，安装按钮只出现在具体子包上。勾选「仅移动端可用」后按真集合分页：过滤条件不再写进搜索词，页码按实际条数算（此前仍按四千多条算出 48 页），列表为空时提示「其余插件的安卓兼容性还没验证过」。

### 5. 应用内更新拆成「检查」与「下载」两步（#485）

设置页新增一级分区「应用更新」（原生管理中心同一形态），检查与下载是两枚独立按钮，版本号独立成文本行。

修掉的三个缺陷：更新按钮点了没有任何反馈、再点一次会静默下载上百 MB（观察者注册被后来者顶掉，回调打不到渲染）；壳侧的 sha256 校验长期恒跳过、实际只剩体积比对（它找的 `*.apk.sha256` 发布链从不产出，真摘要在 MANIFEST.txt 里）；设置页在需授权态点「授权后继续安装」永远回到没有待安装项的状态。

版本号确认改走六档镜像回退，任一档解析出版本号即停，全失败按网络类与服务类分开报告，绝不返回「已是最新」。

### 6. 旧 WebView 设备也能用隔离浏览器（#498、#500、#523）

隔离浏览需要 WebView 114 起的多档案能力。WebView 110 这类老内核此前被拒绝，内置浏览器整块不可用。

本版建立三档模型：WebView 114 起走会话级隔离；老内核走独立渲染进程加数据目录后缀，进程边界即隔离；再老则如实报不可用。老内核设备上，页面事件、触摸、按键、截图、视口测量都跨进程转发。状态面新增隔离档位字段，按实际能力如实上报。

同一面还修掉一处性能缺陷（#540）：老内核档的触摸转发此前每帧都是一次同步跨进程往返，滑一次网页会把主线程整段停顿、逼近 ANR 阈值。现在改为单向投递并在渲染侧合帧。

## 修复

### 7. 任务完成通知不再提前弹（#561）

引擎还在「运行中」时，通知栏已经弹出「任务完成」。真因是完成标记挂在每条助手消息上写，不等一轮结束。本版把写入点移到轮次结束，并且只在该轮结局会弹通知时才写，被中断或被取消的轮次不写。

### 8. 无障碍通道的在线状态不再误报（#648、#666）

控制轮询与无障碍是两条独立生命线，而且轮询本来就设计成无障碍关着也能跑。旧判定把「轮询心跳新鲜」当成「无障碍在线」的证据，于是无障碍服务死掉之后界面照旧显示在线，实际每条操作都返回不可用。

本版只认「印记里声明的启用位 + 新鲜心跳」；轮询新鲜度改成单独一行诊断信息暴露，信息保留但不再冒充在线证据。

同时补上自愈：无障碍服务被系统强制停止后，印记里的启用标记会残留为已启用。现在服务确实未绑定时回写否定值并清掉心跳键，重连时改回真值，两侧不再长期不一致。这个回写只据「服务未绑定」这一确定事实，不据任何一次操作的成败——操作抛异常、超时都属「服务在场但失败」，原因未知，一律不回写。

### 9. 引擎起不来时诊断日志不再空白（#657、#663）

引擎拒绝启动时诊断日志是空的，只有系统日志一行，用户无法自行诊断。真因是七条失败出口里没有一条写这个文件，其中两条还被调用方的提前返回跳过。

本版把所有失败出口收敛到一个统一出口，新增出口只要走它就不可能忘记落盘。设备实测：把 Hard 清单从内嵌资产移除后重构建装机，冷启得到恰好一条可诊断记录，此前这个场景完全静默。

### 10. 快照指纹发布失败不再毁掉恢复点（#685、#692、#755）

指纹是快照事务的提交点。原子发布失败后原实现还留了一段直写回退，那一步恰好会截断旧指纹——发布失败反而把恢复点拿走了。本版改为「先写完整临时文件，发布不成功就报错且不碰目标」，失败会进入既有的回滚路径。

### 11. 快照刷新窗口内的启动请求不再被静默丢弃（#522、#650、#717）

刷新期间抢不到世代所有权时，旧的启动路径直接返回：不启动引擎、不改相位、也不落盘，用户看到的是「点了没反应」。本版按情形分别处置：已销毁的如实回执；正在运行的留痕并有界等待后续跑；安全模式重启在停旧引擎之前先判跨进程事务，避免用户白等一整轮刷新。

没有事务在场时也不再只写一行日志就收手，改为 200ms 步进、3 秒预算的有界重试，取得所有权立刻续跑，超时如实记一条专用代码。

启动结果改成三态回报（已发起、刷新中让行、拒绝），「让行」不再冒充「已发起」；修复助手的「重启引擎」也不会再把刻意让行呈现成重启失败、据而去抢正在写快照的持有者。

### 12. 修复门不再吞掉活页面的就绪报文（#567）

小米 14 真机连续五轮启动：页面每一轮都活着并上报就绪，但持久修复门永远清不掉，用户每轮都看到「引擎仍无法启动」，唯一出口是清数据或重启设备。本版让就绪报文到达即清门并留一条痕迹；插件树失败仍然以失败为准，不会被就绪覆盖。

### 13. 没有创建时间的文件系统上引擎端口能正常采纳（#490、#522）

部分模拟器与文件系统不报告文件创建时间，该值恒为 0，旧判据把它当「不属于本代进程」而拒绝采纳引擎端点。于是引擎明明已经健康监听，仍被判启动失败、两次之后落成持久修复门。本版在创建时间缺席时降级为按修改时间判定，修改时间闸门与「日志已存在即拒启」的隔离检查都保留。

### 14. 会话删除不再卡在「正在删除」（#493、#496、#503、#504、#506、#510）

点删除后弹窗一直转圈，引擎日志里一条路由命中都没有——请求卡在浏览器网络层，挂在重启前的死连接上。本版把单次超时从 15 秒降到 2 秒、最多尝试三次（每次新连接，通常 2.2 秒内完成），并在 4 秒无结果时重载页面重建连接，重载后自动续做这条删除；续做失败会给出可见提示，不再「闪一下、会话还在、零提示」。

删除当前打开的会话后要回到新对话，此前靠匹配「新会话」文案，而上游按钮的无障碍名是「在“X”中新建会话」，匹配不上就退回整页重载、把已删的会话又恢复回来。本版改按上游的类名定位、文案只作兜底，并优先走上游工作区的清理入口（与归档同一条路）。删的不是当前会话时也不再整页重载。

### 15. 旧内核 WebView 上模型选择器不显示（#619、#624）

用户报障：内核低于 Chrome 110 的 WebView 上，模型胶囊不显示，点开模型选择只有搜索框和一行红字 `groups.toSorted is not a function`。注入层补上 `toSorted`、`toReversed`、`toSpliced`、`with` 与 `findLast`、`findLastIndex`，各方法独立判缺、不改写接收者、原生在场时不覆盖。

这些补齐方法改为不可枚举安装：此前用赋值方式装上去，普通数组的 `for...in` 会多出六个方法名，页面上按属性遍历的代码会看到不存在的键。同批收口了 `Array.prototype.at` 与 `String.prototype.replaceAll`。

另外在模块系统边界加了一层守卫：插件模块导出 undefined 组件时，槽位系统会抛 React 错误并把整块渲染吞掉；守卫把这类注册项渲染成空并在控制台留一条警告，其余调用原样透传。

### 16. 截图与附件下载不再堆积资源（#672、#687、#717、#721）

浏览器截图每次都在磁盘留下 PNG，此前没有删除点，工具描述里「读完即删」的说法与实现不符。现在按 1 小时有效期、最多 32 张、总计 128 MiB 三个上限回收，只认自己产出的文件名，回收失败只跳过不抛错；截图发布后立刻执行上限。

附件下载改为带背压的流式管道，客户端断开时销毁源流，上限 256 MiB，超限在写状态行之前就以 413 拒绝。文件打开通道里六处「超时或超量」分支此前先拆连接再写状态码，状态行根本发不出去、客户端只看到连接重置；改为先答复再丢弃剩余请求体。

### 17. 通知不再因渠道被删而永久静默（#570、#578、#588）

用户在系统设置里删掉通知渠道后，该类通知被系统静默丢弃，而壳侧缓存与印记仍是旧值，唯一出路是清数据重装。本版缓存与印记两条命中路径都校验渠道是否还在，已删则按同 ID 重建。

同一批修复还包括：多问通知里两个同名选项共享同一个底层意图，点第一问实际提交了第二问的答案（第一问永久无解）；通知补投与首次投递在主线程做批量文件读写，撞 10 秒无响应预算；通知投递的落盘改为原子替换，崩溃窗口内不会写出半行被跳过的记录。

### 18. 语言切回「跟随系统」不再被钉成固定语言（#488、#494）

引擎在页面加载与配置推送时会自己发布多次语言，旧逻辑把其中一次当用户选择写回壳偏好，于是「跟随系统」被钉成设备语言，之后系统语言变了界面也不跟着变。

本版只认「页面内真实交互之后到达」的语言值，并在回写前与当前显示值比较，相同即忽略。设置页里重复的两行语言收敛为上游那一行：跟随系统改为启动时解析（中文语系写 zh，其它一律 en），用户显式选过之后不再被覆盖。

### 19. 市场勾选「仅移动端可用」真的生效（#507、#517、#541）

勾选后仍出现「原生？」「未验证」条目，勾选前后几乎无差别。真因是服务端判据只剔掉少数桌面独占条目，而目录里绝大多数插件根本不在兼容白名单里；过滤状态还被编码进搜索词，以 `mobile:` 开头的真实关键字会被吞掉。

本版只放行已验证兼容的包，过滤改走独立查询参数，勾选状态自持，搜索框只装用户真正的关键字。原实现还就地改写带缓存的结果数组，取消勾选后列表仍是过滤后的短列表——用户视角是「取消勾选没反应」，改为先展开新对象再过滤。

### 20. 设置页的返回不再一次退到列表（#546、#557、#558）

用户在关于页按返回，一次退回设置列表而不是回到上一页。真因是系统返回走的是「点蒙层」与「Escape」两条路，绕过了上一页记账；而过渡期里第一行被标成当前项，历史记账把「通用设置」误记成上一页，导致任何二级页返回都跳到通用设置。本版让蒙层与 Escape 走同一条回退判据，并引入「详情页是否落定」，过渡期只等不记。

「关于」入口也一并收敛：此前只要页面上有一行写着「版本 1.2.3」的短信息就会被隐藏并被替换成关于入口；现在只认精确的「当前版本」文案，找不到就什么都不做。导航里那条「关于」按「是否曾接管成功」收起，离开分区后不再冒出来，插件重载也不会变成两个入口。

### 21. 抽屉收起后浮层菜单不再残留（#491）

工作区行的「…」菜单是挂到页面根部的浮层，开着时用折叠按钮、左滑手势或系统返回收起抽屉，菜单仍停在原地且可点，删除工作区这类破坏性操作仍可误触。本版监听「抽屉由开到合」这个所有收起路径的唯一汇总点，翻转时通知页面把各瞬态浮层按各自的外部关闭判据收掉。手机形态才介入，展开方向与初始收起态不触发。

### 22. 虚拟屏画面不再拉伸，展开的弹层不再被盖住（#499、#526）

真机平板上虚拟屏预览被拉伸变形、侧栏窄时看不全，侧栏展开收起或输入法弹出时出现半截画面，点右上角三个点展开的标签列表被画面整块盖住。

比例的真因是内容尺寸取的是建屏瞬间的快照，而虚拟屏可随内容旋转，翻转后快照已失效；「半截画面」是横向与纵向用了两套缩放基准。本版把几何抽成纯函数，尺寸改为优先读实时值、快照只作兜底，两个方向统一基准，并补上显示变化的监听。遮挡的真因是画面挂在 Activity 根布局、位于网页层之上，页面里的层级再高也压不过它；改为把「弹层已展开」发布成页面级信号，画面据此暂时隐藏、收起即恢复。预览里还加了全屏浮钮。

### 23. 虚拟屏空闲回收恢复工作（#671、#692、#694、#753）

会话「使用即续期」的入口此前全仓零调用，空闲回收退化成一刀切：建屏十分钟后必被回收，哪怕一直在用。本版在使用点补上续期（状态查询与屏幕列表有意不续期——轮询不构成使用，否则永远不回收），并给触摸路径共享的记录表加锁，避免与回收、生命周期变更竞态。

### 24. 快照解压不再中途误报超限（#680）

解压的总量上限一直是 8 GiB，但进度回调里的已完成字节被重复累加了一次，计数跑到真实值的一半就撞上限。于是磁盘空间明明够，解压却在中途报超限失败，应用直接起不来。本版去掉这处重复累加，按真实进度计。

### 25. 菜单键与媒体键不再在低版本上假装可用（#681）

「菜单」与「媒体播放或暂停」这两个系统按键是 Android 16（API 36）才有的常量，此前被错标成 API 31。于是 Android 12 到 15 的设备也把它们当成可用能力暴露出去，真按下去平台恒返回失败、界面毫无反应。本版按真实版本门控：Android 16 及以上可用，更低版本不再宣传这两个按键。

## UI·交互

### 26. 三页设置项统一到上游行规（#486、#505）

通用设置里的安卓自建项，以及通知、手机控制、开发者选项三页，此前是自绘的一整套控件：16px 原生勾选框、36px 描边按钮、13px 提示，和同一张列表里的上游行并排就是两种语言。

现在行骨架统一为「标题 14/20 + 说明 12/18 + 右侧控件」，8px 上下距与 0.5px 分隔线；开关一律换成上游的 Switch，动作按钮对齐上游的小号按钮；长路径允许任意位置断行，不再压到按钮上；同一类名的行距在两页之间不再一个 8px、一个 16px。顺带修掉「通知动作按钮被挤成两行」与「手机控制页完全没吃到新样式」两处实现缺陷。

### 27. 关于页与意见反馈入口（#542、#545、#589）

「关于」从一行版本号变成可进入的页面；意见反馈从账号菜单搬到通用设置最下方，账号插件缺席时回退到默认问卷地址。另修掉一处入口缺失与返回焦点不可见的问题。

### 28. 外观三张主题卡片压成一行（#486）

上游给三张主题卡片写的是固定宽度，竖屏下必然一张一行，整块占到三百多像素，是设置页里最占纵向空间的一项。本版在手机形态下把它压成一行，老内核不支持相应选择器时退化为「标题在上、三个选项一行」。

### 29. 检查更新按钮重绘（#576）

检查更新按钮改按管理中心口径绘制（8dp 圆角），不再沿用启动页的胶囊形态。

## 安全·桥协议

### 30. 屏幕范围门禁补齐十余类绕过写法（#509、#525、#717、#756、#759）

屏幕范围设成「仅虚拟屏」时，壳侧与引擎侧各有一道门禁判据挡住对真实屏的读写。本轮以真机实测逐条补齐可以绕过的写法：管道把命令喂给裸 shell（载荷不可见）、双引号内的命令替换与反引号、`eval` 载荷、shell 注释被当成命令词、命令词位置带引号、`-d` 短选项与长选项混用同一条正则、`input` 的来源位置词与 `press`、`trap` 与尾随参数、`--` 选项终结符，以及 `sh -lc`、`-ec`、`-xc` 这类短选项簇与带参数的 `-o`。

每一条都在两侧同改（引擎侧判据与壳侧执行点），并用双向的跨语言用例锁死：改了一侧忘了另一侧会立刻判红。判据不是「一律拒绝」——已注册虚拟屏的合法调用、参数位置的引号、`echo "screencap"` 这类只是打印的写法都有对照用例保证仍然放行。

### 31. 修复工具的护栏补两类盲区（#512）

修复助手执行的命令护栏此前有两类系统性盲区：引号拆词（把命令或凭据文件名拆开写）能骗过字面匹配；变量间接（先把路径写进变量，再对变量做删除）在按位置关系匹配时失明。现在判据先剔除引号字符再重匹配，并对删除、移动、复制、改写属主等破坏性命令同段引用变量一律拒绝——宁可误拒。护栏的定位不变：它防模型跑偏，真边界仍是应用沙箱与双授权门。

### 32. 诊断日志与错误回显的脱敏补齐（#508、#516、#673、#751）

三类漏网形态：带前缀的会话 cookie 头（抓包导出的整行此前被放过）、`export` 前缀的密钥行、以及行首锚定导致带前缀的日志格式漏脱敏。

启动诊断里的失败详情与调用栈此前只在注释里约定「不含凭据」，没有强制——而引擎启动异常的消息里可能带着含令牌的引擎地址，诊断包会离开进程。本版把这两条出口统一过脱敏函数，并补上修复助手网关错误的回显打码。

### 33. 更新下载改为 fail-closed（#513、#534）

元数据缺少摘要时第三方镜像产物不再直通安装器（无摘要可校验就宁可下载失败）；重定向从「盲跟任意跳转」改为手工限域跟随，每一跳的最终域必须在白名单内、仅 https、最多三跳，越域整链放弃走下一条线路。元数据读取加 1 MiB 上限。正常发布链恒带摘要，行为不变。

### 34. 落盘与事务的原子性收口（#511、#518、#531、#595）

修复助手会话、决策队列、快照合并配置三处此前在原子替换失败后回退成直接覆写目标，崩溃窗口内会写出半截文件：修复对话被当成不存在而整段丢失，用户的作答被解析跳过而静默丢失。三处统一改走仓内标准的原子替换，直写只保留为两段都失败时的极端兜底。

快照事务的发布目标改为显式拒绝非普通文件——旧判据只对错误码断言，底层把文件改名到目录上同样会失败并返回同一个码，于是「显式检查被删掉」这件事测不出来。

### 35. 文件范围暴露加调用点门禁（#585）

新增门禁检查文件共享的路径映射，避免把过宽的文件范围暴露出去；解析配置属性时先解码再做范围判定。

### 36. 隔离浏览器的视口预设真正生效（#498、#523）

隔离浏览器支持挑选分辨率档（手机竖屏、桌面 1280x720 等），此前在旧内核设备上会出现「状态说按某个档排版，页面实际仍按手机尺寸排版」的分叉：调用方按回报值算坐标必然错位，模型按回报尺寸截的图也对不上。

根因是兼容档执行位的两处缺口：判断「要不要重建页面」用的是本地视图是否存在，而该档的页面在独立渲染进程里、本地视图永远是空的，于是设了视口从不重建，注入的视口脚本装不上；重建之后又没有重算投影矩形，沿用上一个档位遗留的尺寸。另有一处取值顺序问题——舞台尺寸排在显式请求之前，侧栏收起（用户不看屏幕，是常态）时显式请求被历史值顶掉。

三处一并修正后，上报值与实际排版值一致。回归双向验证：桌面 1280x720 精确生效；原有的手机竖屏 390x844 不回归（高度按 letterbox 取整容差通过）。本项缺陷在更早版本就已存在，只是此前旧内核设备根本走不到这条通路；本版让它们第一次真正用上隔离浏览器，才把它暴露出来。

## 构建·发布

- **仓库卫生（#743、#747）**：删掉两份写死 Windows 缓存路径的 `.npmrc`——它在非 Windows 主机上被当成相对路径，每次 npm 调用都在仓库里新建缓存目录；已入库的这批缓存文件一并清掉，忽略规则改为按目录名兜底。
- **CI 稳定性（#702、#704、#707）**：五个工作流补上并发控制（PR 上连推两次不再并行跑两份、避免旧提交的结果盖住新提交；发布链全局单飞），所有执行 job 补上超时（此前一律吃平台默认的六小时，卡住即白烧）。可复用工作流的调用点单独隔离并发组。
- **本地构建防线（#668、#700、#701）**：dev 档此前会静默产出「能装、界面能起，但引擎永远起不来」的包——把 arm64 快照装到 x86_64 设备上，链接器报架构不匹配，任何启动测量都会得出反向结论。现在构建前流式读取归档内二进制的架构并拒绝不匹配的组合；未显式指定目标架构时从已连设备推断，推断不出来只提示不阻断；缺失的快照摘要补齐并加装机前自检。
- **门禁换代**：新增中英文案一致性门禁（资源层键集合加代码层翻译调用，漏英文此前构建、单测、CI 全绿）、镜像前缀表一致性门禁、屏幕范围双向用例台账；补丁夹具换代到本代引擎；多条门禁把判据抽成纯函数并在主体内静默自证（变异即判红），修掉若干「拿旧产物判绿」与「声明即视为执行」的假绿口子（#647、#649、#652、#659、#661、#712、#727、#742、#750、#754）。Kotlin 单测基线随之升档到 1912 例。

## 安装与升级

- 覆盖安装即可（versionCode 54 > 53），不要求先卸载，会话与设置保留。
- 快照已变更：升级后若触发快照刷新，请等 `.snapshot-fingerprint` 翻转且 `.snapshot-transaction` 消失再操作（通常 8-12 分钟）。期间不要强杀进程，也不要在设备上跑验收套件（会得到假失败）。

## 已知限制

- 控制台的 TUI 渲染仍走纯文本容器：全屏程序画的边框字符会显示为 `lqk`、`mqqq` 这类替代字符，功能不受影响（键盘输入、作业控制、程序本身都正常）。这是渲染层的问题而非终端的问题，换成 ANSI 渲染器即可。
- 一键换源只覆盖 apt 源，不碰 `sources.list.d` 与 npm registry；循环切换只收了六个常用国内镜像，其余仍可在控制台里用 `pkg` 自选。
- 隔离浏览在 WebView 114 以下走「独立进程加数据目录后缀」档：所有会话共享同一个浏览器档案（与引擎的 cookie、存储隔离），不是逐会话隔离。更老的核仍判不可用。
- 会话删除的活动探测存在毫秒级的探测与删除竞态：探测到空闲、删除前会话恰好开始运行的情况下无法拦下。引擎侧没有可拿的锁，跨进程锁的复杂度不抵收益，按已知限制登记。
- 市场「仅移动端可用」只放行白名单里标记为可用的插件，该表当前已登记的条数以 `scripts/patches/data/compat-map.json` 为准；勾选后列表会明显变短，这是预期行为，未登记的插件一律按「未验证」处理。
- 控制台的 PTY 中继会多拉起一个进程，首次建立约有 0.7 秒一次性开销；缺少运行时依赖时退化为原来的非 PTY 模式，并在状态栏如实说明。
- 引擎追版到 0.2.1-rc.3 带来的三项上游变化（插件菜单、草稿保留、模型列表对齐）本轮未逐项做设备验收。
- 虚拟屏在未安装 Shizuku 的设备上不可用，状态如实显示 `shizuku-absent` 并给出引导。本版未改变该前置要求。
- 隔离浏览的视口预设（如桌面 1280x720）在 WebView 114 以下走 tier-2 通路时，页面按请求值排版、状态回报同值；若舞台物理尺寸小于所需，按同一比例 letterbox 缩放，实际 CSS 宽高可能与请求值有 1-2 px 取整差异。
