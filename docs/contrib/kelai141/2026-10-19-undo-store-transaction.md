# 快照写入与回收共用存储事务

关联 #423 第 6 项、#428 第 12、13 项，以及清单安全修复的跨进程前置。

原 blob 写入先于 manifest，GC 会在引用尚未发布时误删内容；自动 GC 还漏了消息撤销批次的 beforeHash，并使用删除前列表延迟回收。固定临时名及吞掉 rename 错误会放大问题。

现在快照创建、导入、元数据更新、恢复、消息记录与回收共用同一存储根的内核互斥端点，进程内 FIFO 串行，调用链可重入。Windows 使用命名管道，Linux/Android 使用抽象 Unix socket；不支持抽象 socket 的早期 Node 20 与 macOS 使用哈希 loopback 端口。占用或冲突一律拒绝写/删；无 PID 或年龄接管。进程死亡由内核释放，不留下磁盘锁。端口哈希碰撞只能导致保守拒绝，不能绕过互斥。

工具追踪覆盖 writeBlob 到 appendMessageOp 的完整窗口。工具执行后追踪失败不会再次执行工具。blob 使用唯一临时文件并验证 hash；发布失败不再伪装成已有内容。快照与导入先写本轮 staging，完成后原子发布，失败只清理本轮 staging。旧快照、manifest、消息 JSON 格式不变，不清空或迁移旧存储。

GC 在锁内重新收集所有快照及消息引用。损坏或不认识的 manifest、消息记录使回收停止，任何 blob 都不删。只删除符合 SHA-1 文件名的孤儿；未知文件和临时文件原样保留。自动清理在删快照前也执行完整校验，清理后用最新引用扫描。

验证：Windows 和 WSL Node 24 共 13 项新增回归通过。独立子进程持锁阻止 GC；杀死 fixture 子进程后重试成功；1 小时旧孤儿被新快照复用时仍保留；损坏清单/消息零删除；自动 GC 保留消息引用并回收已淘汰快照的独占 blob；并发快照/消息发布完整。既有 safe-mode-transaction 6 项通过。undo-scan-and-time 5 项因未配置可解析 dsh-tools 的 DSH_ROOT 未运行成功，不能算通过。补丁自洽检查 15/15 通过。

未做设备验证：Android 内核端点、真实插件钩子与页面仍需本候选三层验收。旧版本进程不会遵守新互斥协议；部署时必须确保同一存储的运行时均更新，不能与旧局外服务并行写同一目录。macOS 尚未实机验证。

内核 IPC 生命周期依据：https://nodejs.org/api/net.html#ipc-support 。
