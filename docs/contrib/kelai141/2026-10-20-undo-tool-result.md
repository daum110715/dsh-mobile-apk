# 工具执行结果与撤销追踪隔离

关联 #444、#445、#446、#447 及协调仓镜像 #127、#128、#129、#130。

工具前置钩子先持久写入 pending 预留，执行完成后再补 after 状态。此前完成或裁剪失败会让 `finally` 抛错，覆盖工具已经返回的结果；`next` 自身抛错时，外层 catch 也可能吞掉原异常。超过 256 KiB 的直通分支还丢掉了 `next` 的返回值。

现在主执行结果和原异常原样返回。完成记录与裁剪属于旁路记账，失败只记录警告并保留 pending 旧账本，不能重执行 `next`；`next` 开始前的追踪初始化失败仍会执行且仅执行一次工具。大于 256 KiB 的文件直接透传结果。

测试从真实 `lib/index.js` 提取注册的 `tools/pre-execute` 钩子到 vm 执行，故障注入 `completeMessageOp`、`pruneMessageOps` 与 `next` 抛错，并覆盖大文件返回值和初始化失败回退。

未做设备验证：本改动为工具钩子错误语义修复，需在 APK 候选的三层验收中复核真实宿主行为。
